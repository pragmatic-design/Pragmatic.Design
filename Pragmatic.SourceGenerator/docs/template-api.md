# CSharpTemplate API Reference

`CSharpTemplate` is the abstract base class that all Pragmatic source generator templates extend. Instead of building source code with raw `StringBuilder` concatenation, templates use structured methods that handle indentation, braces, access modifiers, and parameter formatting automatically. This produces consistent, readable generated code while keeping template logic focused on *what* to generate rather than *how* to format it.

---

## 1. Overview

Every template follows the same lifecycle. You inherit from `CSharpTemplate`, implement two abstract methods, and the base class handles rendering the file header (auto-generated comment, `#nullable enable`, usings, namespace) and assembling the final `SourceText`.

The output type is `Artifact`, a readonly struct pairing a hint name with the rendered source:

```csharp
internal readonly struct Artifact
{
    public string HintName { get; init; }
    public SourceText Source { get; init; }

    /// True when the template produced no content — the normal outcome when Validate() is false.
    public bool IsEmpty => Source is null || Source.Length == 0;

    public Artifact(string hintName, SourceText source);
    public static Artifact FromString(string hintName, string content);
}
```

`FromString` normalizes line endings to CRLF before wrapping the content in a UTF-8 `SourceText`; `ToSourceText()` does the same for the template's own rendered body.

### Handing the artifact to Roslyn

There is exactly one way to emit an artifact:

```csharp
ctx.AddSource(artifact);
```

`SourceOutput.AddSource` (`shared/SourceGen/SourceOutput.cs`) is an extension on `SourceProductionContext`. It checks `artifact.IsEmpty` and **skips** the file, otherwise forwarding to Roslyn's own two-argument `AddSource`. (An instance method always wins overload resolution over an extension, so the forwarding call does not recurse.)

Do not call `ctx.AddSource(artifact.HintName, artifact.Source)`. A template whose `Validate()` returns `false` renders to *empty* content rather than to nothing (that is how every template says "there is nothing to generate here"), and the two-argument call writes that empty content into the compilation as a real zero-byte `.g.cs`. It compiles, but it fills the generated-files list with noise and erases the difference between "deliberately nothing" and "the template silently produced nothing".

Templates are split across four partial files for maintainability:

| File | Contents |
|------|----------|
| `CSharpTemplate.cs` | Core writing, usings, blocks, comments, nested types, rendering |
| `CSharpTemplate.Types.cs` | `Class()`, `Struct()`, `Record()`, `RecordStruct()` |
| `CSharpTemplate.Members.cs` | `Field()`, `Property()`, `Method()`, `Constructor()`, operators |
| `CSharpTemplate.ControlFlow.cs` | `If()`, `ElseIf()`, `Else()`, `Switch()`, `Case()`, `Return()` |

> `CSharpTemplate` is the only supported way to emit source. `StringBuilder`, string concatenation, and inline builders are prohibited (`docs/CONVENTIONS.md`). There is no `CSharpBuilder` API: a comment or doc naming one is pointing at nothing.

## 2. Abstract and Virtual Members

These are the methods you implement or override when creating a template.

### Required

| Member | Signature | Purpose |
|--------|-----------|---------|
| `RenderOutput()` | `public abstract Artifact RenderOutput()` | Returns the hint name and rendered source text. Call `ToSourceText()` to get the `SourceText`. |
| `RenderFile()` | `public abstract void RenderFile()` | Writes the file body using template methods. Called internally by `ToString()`. |

### Optional Overrides

| Member | Default | Purpose |
|--------|---------|---------|
| `Validate()` | `return true` | Return `false` to skip generation entirely. `ToString()` returns `null`, `ToSourceText()` renders empty content, and `ctx.AddSource(artifact)` skips the file. Nothing is reported: a missing output is silent by design. |
| `GeneratorName` | `null` | Appears in `// Generated by {GeneratorName} v{version}` header. |
| `SourceInfo` | `null` | Appears in `// Source: {SourceInfo}` header. |
| `TriggerInfo` | `null` | Appears in `// Trigger: {TriggerInfo}` header. |

### Example

```csharp
internal sealed class OrderTemplate : CSharpTemplate
{
    private readonly OrderModel _model;
    public OrderTemplate(OrderModel model) => _model = model;

    protected override string? GeneratorName => "Pragmatic.SourceGenerator/Orders";
    protected override string? SourceInfo => $"{_model.TypeName} from {_model.Namespace}";
    protected override string? TriggerInfo => $"[DomainAction] on {_model.TypeName}";
    protected override bool Validate() => _model.IsPartial;

    public override Artifact RenderOutput() => new(
        VirtualFolderHints.ForType(_model.TypeName, "Invoker", _model.Namespace),
        ToSourceText());

    public override void RenderFile()
    {
        AppendNamespace(_model.Namespace);
        AppendLine();
        Class(_model.TypeName, RenderBody,
            modifiers: new ClassModifiers { Partial = true });
    }

    private void RenderBody() { /* ... */ }
}
```

## 3. File Header

The file header is rendered automatically by the base class after `RenderFile()` completes. You control it by calling `AddUsing()`, `AddAlias()`, and `AppendNamespace()` during `RenderFile()`, and by overriding the header properties.

### AddUsing / AddUsings

Registers a `using` directive. Duplicates are ignored. The `<global namespace>` string is silently skipped.

```csharp
AddUsing("System.Collections.Immutable");
AddUsings("System", "System.Linq", "System.Threading.Tasks");
```

### AddAlias

Registers a `using` alias directive such as `using Foo = Some.Long.Namespace.Foo;`.

```csharp
AddAlias("OrderResult", "Pragmatic.Result.Result<Order, OrderError>");
// Emits: using OrderResult = Pragmatic.Result.Result<Order, OrderError>;
```

### AppendNamespace

Writes a file-scoped namespace declaration. Typically called at the start of `RenderFile()`.

```csharp
AppendNamespace("MyApp.Orders");
// Emits: namespace MyApp.Orders;
```

### Auto-Generated Header

The rendered header always starts with `// <auto-generated/>` and `#nullable enable`. When the optional properties are set, additional comment lines are added:

```
// <auto-generated/>
// Generated by Pragmatic.SourceGenerator/Orders v1.2.3
// Source: PlaceOrder from MyApp.Orders
// Trigger: [DomainAction] on PlaceOrder
#nullable enable

using System.Collections.Immutable;

namespace MyApp.Orders;
```

The version (`v1.2.3`) comes from the assembly version of the SG assembly at build time.

## 4. Type Declarations

These methods generate type declarations with proper access modifiers, inheritance, and braces. Each accepts an `Action body` delegate where you write the type's members.

### Class

```csharp
protected void Class(
    string className,
    Action body,
    string? baseType = null,
    List<string>? interfaces = null,
    AccessModifier accessModifier = AccessModifier.Public,
    ClassModifiers modifiers = default)
```

```csharp
Class("OrderRepository", RenderRepositoryBody,
    baseType: "RepositoryBase<Order>",
    interfaces: ["IOrderRepository"],
    accessModifier: AccessModifier.Public,
    modifiers: new ClassModifiers { Sealed = true });
// Emits:
// public sealed class OrderRepository : RepositoryBase<Order>, IOrderRepository
// {
//     ...
// }
```

### Struct

```csharp
protected void Struct(
    string structName,
    Action body,
    List<string>? interfaces = null,
    AccessModifier accessModifier = AccessModifier.Public,
    ClassModifiers modifiers = default)
```

### Record / RecordStruct

Records and record structs accept an optional `parameters` list for positional parameters:

```csharp
protected void Record(
    string recordName,
    Action body,
    List<MethodParameter>? parameters = null,
    List<string>? interfaces = null,
    AccessModifier accessModifier = AccessModifier.Public,
    ClassModifiers modifiers = default)
```

```csharp
Record("OrderCreatedEvent", () => { /* body */ },
    parameters: [
        new MethodParameter("Guid", "OrderId"),
        new MethodParameter("DateTime", "CreatedAt")
    ],
    interfaces: ["IDomainEvent"]);
// Emits:
// public record OrderCreatedEvent(Guid orderId,
//                                 DateTime createdAt) : IDomainEvent
// {
//     ...
// }
```

### ClassModifiers

The `ClassModifiers` struct controls keyword placement in the declaration. Keywords are emitted in order: access, static, abstract, sealed, readonly, partial.

```csharp
protected struct ClassModifiers
{
    public bool Partial { get; init; }    // partial class/struct/record
    public bool Abstract { get; init; }   // abstract class
    public bool Sealed { get; init; }     // sealed class
    public bool IsStatic { get; init; }   // static class
    public bool IsReadOnly { get; init; } // readonly struct
}
```

### AccessModifier Enum

```csharp
internal enum AccessModifier
{
    Public,             // public
    Private,            // private
    Protected,          // protected
    Internal,           // internal
    ProtectedInternal,  // protected internal
    PrivateProtected,   // private protected
    NotApplicable       // (no access modifier emitted)
}
```

### ParseAccessibility Helper

Converts a string from Roslyn (e.g., `"public"`, `"internal"`) to the `AccessModifier` enum. Available in `TemplateHelpers`:

```csharp
var access = TemplateHelpers.ParseAccessibility(_model.Accessibility);
```

## 5. Members

### Field

Generates a field declaration with optional modifiers and initializer.

```csharp
protected void Field(
    string fieldName,
    string type,
    AccessModifier accessModifier = AccessModifier.Private,
    bool isReadOnly = false,
    bool isStatic = false,
    string? initializer = null)
```

```csharp
Field("_logger", "ILogger<OrderService>", isReadOnly: true);
// Emits: private readonly ILogger<OrderService> _logger;

Field("DefaultTimeout", "TimeSpan", AccessModifier.Private, isReadOnly: true, isStatic: true,
    initializer: "TimeSpan.FromSeconds(30)");
// Emits: private static readonly TimeSpan DefaultTimeout = TimeSpan.FromSeconds(30);
```

### Property

Generates an auto property or a property with get/set bodies.

```csharp
protected void Property(
    string propertyName,
    string type,
    AccessModifier accessModifier = AccessModifier.Public,
    bool isStatic = false,
    bool isReadOnly = false,
    string? defaultValue = null,
    Action? getBody = null,
    Action? setBody = null)
```

```csharp
// Auto property
Property("OrderId", "Guid");
// Emits: public Guid OrderId { get; set; }

// Auto property with default
Property("Status", "OrderStatus", defaultValue: "OrderStatus.Pending");
// Emits: public OrderStatus Status { get; set; } = OrderStatus.Pending;

// Property with bodies
Property("TotalAmount", "decimal", getBody: () =>
{
    Return("Items.Sum(i => i.Price * i.Quantity)");
});
```

### ExpressionProperty

Generates an expression-bodied property (arrow syntax).

```csharp
protected void ExpressionProperty(
    string propertyName,
    string type,
    string expression,
    AccessModifier accessModifier = AccessModifier.Public,
    bool isStatic = false)
```

```csharp
ExpressionProperty("IsEmpty", "bool", "Items.Count == 0");
// Emits: public bool IsEmpty => Items.Count == 0;
```

### PropertyWithGetter

Generates a property with a custom getter block. Useful when you need attributes like `[MethodImpl]` inside the getter body.

```csharp
protected void PropertyWithGetter(
    string propertyName,
    string type,
    Action getterLines,
    AccessModifier accessModifier = AccessModifier.Public,
    bool isStatic = false)
```

### Method

Generates a method declaration with body, parameters, modifiers, and optional attribute.

```csharp
protected void Method(
    string methodName,
    Action body,
    string returnType,
    List<MethodParameter>? parameters = null,
    AccessModifier accessModifier = AccessModifier.Public,
    MethodModifiers modifiers = default,
    string? attribute = null)
```

```csharp
Method("CalculateTotal", () =>
{
    AppendLine("var sum = 0m;");
    AppendLine("foreach (var item in Items)");
    Block(() => AppendLine("sum += item.Price * item.Quantity;"));
    Return("sum");
},
returnType: "decimal",
parameters: [new MethodParameter("IReadOnlyList<OrderItem>", "Items")],
modifiers: new MethodModifiers { IsAsync = true });
```

### ExpressionMethod

Generates an expression-bodied method.

```csharp
ExpressionMethod("GetDisplayName", "$\"{FirstName} {LastName}\"", "string");
// Emits: public string GetDisplayName() => $"{FirstName} {LastName}";
```

### GenericMethod

Generates a method with type parameters.

```csharp
GenericMethod("Create", ["TEntity"], () =>
{
    Return("new TEntity()");
},
returnType: "TEntity");
// Emits: public TEntity Create<TEntity>()
// {
//     return new TEntity();
// }
```

### Constructor

Generates a constructor with optional base call.

```csharp
protected void Constructor(
    string className,
    Action body,
    List<MethodParameter>? parameters = null,
    AccessModifier accessModifier = AccessModifier.Public,
    string? baseCall = null,
    bool isStatic = false)
```

```csharp
Constructor("OrderService", () =>
{
    AppendLine("_repository = repository;");
},
parameters: [new MethodParameter("IOrderRepository", "Repository")],
baseCall: "logger");
// Emits: public OrderService(IOrderRepository repository) : base(logger)
// {
//     _repository = repository;
// }
```

### ImplicitOperator

Generates an implicit conversion operator.

```csharp
ImplicitOperator("OrderId value", "Guid", "value.Value");
// Emits: public static implicit operator Guid(OrderId value) => value.Value;
```

### MethodParameter

The `MethodParameter` readonly struct describes a method or constructor parameter.

```csharp
protected readonly struct MethodParameter
{
    public string Type { get; init; }
    public string Name { get; init; }
    public bool Nullable { get; init; }
    public bool IsExtension { get; init; }
    public string? DefaultValue { get; init; }
    public string? Attribute { get; init; }
    public bool IsRef { get; init; }
    public bool IsOut { get; init; }

    public MethodParameter(string type, string name, bool nullable = false);
}
```

The `Name` is automatically converted to camelCase in the rendered output.

```csharp
new MethodParameter("IServiceCollection", "Services") { IsExtension = true }
// Renders as: this IServiceCollection services

new MethodParameter("CancellationToken", "CancellationToken") { DefaultValue = "default" }
// Renders as: CancellationToken cancellationToken = default

new MethodParameter("string", "Name", nullable: true)
// Renders as: string? name
```

### MethodModifiers

```csharp
protected struct MethodModifiers
{
    public bool IsStatic { get; init; }
    public bool IsVirtual { get; init; }
    public bool IsOverride { get; init; }
    public bool IsAbstract { get; init; }
    public bool IsSealed { get; init; }
    public bool IsAsync { get; init; }
}
```

## 6. Control Flow

Control flow methods generate `if`/`else`, `switch`/`case`, and statement keywords with proper indentation and braces.

### If / ElseIf / Else

```csharp
If("order.Status == OrderStatus.Pending", () =>
{
    AppendLine("order.Approve();");
});
ElseIf("order.Status == OrderStatus.Approved", () =>
{
    AppendLine("order.Ship();");
});
Else(() =>
{
    AppendLine("throw new InvalidOperationException();");
});
```

### Switch / Case / Default

Generates a `switch` statement with `case` labels.

```csharp
Switch("order.Status", () =>
{
    Case("OrderStatus.Pending", () =>
    {
        AppendLine("ProcessPending(order);");
        Break();
    });
    Case("OrderStatus.Shipped", () =>
    {
        AppendLine("ProcessShipped(order);");
        Break();
    });
    Default(() =>
    {
        AppendLine("throw new NotSupportedException();");
        Break();
    });
});
```

### Return / Break / Continue

```csharp
Return("order.TotalAmount");   // return order.TotalAmount;
Break();                        // break;
Continue();                     // continue;
```

## 7. Documentation

XML documentation methods generate properly formatted doc comments.

```csharp
XmlSummary("Calculates the total amount for the order including tax.");
// /// <summary>
// /// Calculates the total amount for the order including tax.
// /// </summary>

XmlParam("orderId", "The unique identifier of the order.");
// /// <param name="orderId">The unique identifier of the order.</param>

XmlReturns("The total amount including tax.");
// /// <returns>The total amount including tax.</returns>

XmlInheritDoc();
// /// <inheritdoc/>

Comment("This is a workaround for EF Core limitation #12345");
// // This is a workaround for EF Core limitation #12345
```

XML doc methods automatically escape `<`, `>`, and `&` while preserving well-known XML doc tags (`<see>`, `<paramref>`, `<typeparamref>`, `<c>`).

## 8. Low-Level Writing

When the structured methods above do not cover your use case, fall back to these low-level primitives.

### Append / AppendLine

`Append()` writes text on the current line without a newline. `AppendLine()` writes text followed by a newline. Both handle indentation automatically when starting a new line.

```csharp
Append("services");
Append(".AddScoped<");
Append("IOrderRepository");
AppendLine(">();");
// Emits: services.AddScoped<IOrderRepository>();
```

### IncreaseIndent / DecreaseIndent

Manually adjusts the indentation level. Use sparingly -- prefer `Block()`, `Class()`, `Method()`, etc. which manage indentation automatically.

```csharp
AppendLine("{");
IncreaseIndent();
AppendLine("// indented content");
DecreaseIndent();
AppendLine("}");
```

### Block

Writes a braced block with automatic indentation. Optionally prefixed with a modifier string.

```csharp
protected void Block(Action body, string? modifier = null)
```

```csharp
Block(() =>
{
    AppendLine("var x = 1;");
});
// Emits:
// {
//     var x = 1;
// }

Block(() =>
{
    AppendLine("return _value;");
}, "get");
// Emits:
// get
// {
//     return _value;
// }
```

### When to Use Low-Level vs. Structured

| Scenario | Use |
|----------|-----|
| Standard class/method/property | Structured: `Class()`, `Method()`, `Property()` |
| Switch expressions (C# 8+) | Low-level: manual `AppendLine`, `IncreaseIndent()` |
| Inline attribute chains | Low-level: `AppendLine("[Attribute]")` before structured call |
| Custom formatting not covered by API | Low-level: `Append()` + `AppendLine()` |
| LINQ-style chained calls | Low-level: `Append()` for fluent chains |

## 9. Gotchas

Common mistakes when using `CSharpTemplate` and how to avoid them.

### MethodModifiers.IsStatic vs. ClassModifiers.Static

The property names differ between the two structs. `ClassModifiers` uses `IsStatic` (with `Is` prefix) -- but so does `MethodModifiers`. However, `ClassModifiers` uses plain `Partial`, `Abstract`, `Sealed` (no `Is` prefix for those). Double-check which struct you are using.

```csharp
// Class: use IsStatic, Partial, Abstract, Sealed
new ClassModifiers { IsStatic = true, Partial = true }

// Method: use IsStatic, IsVirtual, IsOverride, IsAbstract, IsSealed, IsAsync
new MethodModifiers { IsStatic = true, IsAsync = true }
```

### Switch Expressions Need Manual AppendLine

The `Switch()` method generates a `switch` statement, not a `switch` expression. For switch expressions (which evaluate to a value), you must use low-level writing:

```csharp
AppendLine("var result = status switch");
AppendLine("{");
IncreaseIndent();
AppendLine("OrderStatus.Pending => \"Waiting\",");
AppendLine("OrderStatus.Shipped => \"On the way\",");
AppendLine("_ => \"Unknown\",");
DecreaseIndent();
AppendLine("};");
```

### Block Has No terminateWithSemicolon

The `Block()` method always closes with `}` followed by a newline. It does not support appending a semicolon. If you need `};` (e.g., for object initializers), write the closing manually:

```csharp
AppendLine("var options = new Options");
AppendLine("{");
IncreaseIndent();
AppendLine("Timeout = 30,");
DecreaseIndent();
AppendLine("};");
```

### MethodParameter Auto-CamelCases Name

The `MethodParameter.ToString()` method automatically converts the `Name` property to camelCase. If you pass `"OrderId"`, it renders as `orderId`. This is usually what you want, but be aware of it when the parameter appears in the method body -- use the camelCase form there too.

### Nullable Suffix

`new MethodParameter("string", "Name", nullable: true)` appends `?` only if the `Type` string does not already contain `?`. If your type is `"string?"`, the nullable flag is redundant.

## 10. NamingHelper

When generating derived names (class names, method names, DI registration methods), naive string concatenation can produce doubled suffixes. `NamingHelper.AppendSuffix()` solves this by detecting when the base name already ends with part of the suffix.

### Why It Is Mandatory

Consider a type named `CancelReservationMutation` with a suffix of `MutationInvoker`:

```csharp
// Without NamingHelper:
var name = $"{typeName}MutationInvoker";
// Result: "CancelReservationMutationMutationInvoker"

// With NamingHelper:
var name = NamingHelper.AppendSuffix(typeName, "MutationInvoker");
// Result: "CancelReservationMutationInvoker"
```

### How It Works

The algorithm:
1. If the name already ends with the full suffix, return as-is.
2. For each word boundary in the suffix (uppercase letter), check if the name ends with that prefix of the suffix.
3. If a match is found, append only the remaining portion of the suffix.
4. If no overlap, append the full suffix.

### Examples

| Input Name | Suffix | Result |
|-----------|--------|--------|
| `CancelReservation` | `MutationInvoker` | `CancelReservationMutationInvoker` |
| `CancelReservationMutation` | `MutationInvoker` | `CancelReservationMutationInvoker` |
| `GetOrder` | `Invoker` | `GetOrderInvoker` |
| `GetOrderInvoker` | `Invoker` | `GetOrderInvoker` |
| `Order` | `Repository` | `OrderRepository` |
| `OrderRepository` | `Repository` | `OrderRepository` |

## 11. VirtualFolderHints

`VirtualFolderHints` is the single source of truth for Roslyn hint names. Hint names determine the file name under which generated source appears in IDE Solution Explorer and in build output. Using consistent patterns keeps generated files predictable and sorted logically.

It lives in `Pragmatic.SourceGenerator/src/Pragmatic.SourceGenerator/Core/VirtualFolderHints.cs` (the generator project, **not** `shared/SourceGen/`) and is `internal` to that assembly. The standalone generators that do not link it (Result, Country/Currency/Language) build their hint names themselves.

Slashes in hint names are unreliable across IDE versions (dotnet/roslyn#70859), which is why every pattern below is flat and dot-separated rather than a real folder path.

### Module Hints (Type-First)

In module projects, you search for generated code by entity/action name. The type name comes first.

| Method | Pattern | Example |
|--------|---------|---------|
| `ForType(typeName, artifact, namespacePrefix)` | `{Ns}.{Type}.{Artifact}.g.cs` | `Sales.Invoice.Repository.g.cs` |
| `ForBoundary(name, artifact)` | `_Boundary.{Name}.{Artifact}.g.cs` | `_Boundary.Billing.Interface.g.cs` |
| `ForAssembly(category, ns, ext)` | `_Infra.{Category}.{Ext}.g.cs` | `_Infra.Actions.Registration.g.cs` |
| `ForMetadata(ns, category)` | `_Metadata.{Category}.g.cs` | `_Metadata.Persistence.g.cs` |

### The `namespacePrefix` Parameter

Three helpers take a `namespacePrefix`, and they do **not** treat it the same way:

| Helper | Uses it? |
|--------|----------|
| `ForType` | **Yes.** It becomes the first segment of the hint name. |
| `ForAssembly` | No. The output is one per assembly, so there is nothing to disambiguate. |
| `ForMetadata` | No. Same reason. |

For `ForType` the parameter is optional in the signature but not in practice. Pass `_model.Namespace` every time:

```csharp
VirtualFolderHints.ForType("Invoice", "Repository", "Sales")   // Sales.Invoice.Repository.g.cs
VirtualFolderHints.ForType("Invoice", "Repository")            // Invoice.Repository.g.cs  ← collides
```

Two types with the same simple name in different namespaces (`Sales.Invoice` and `Archive.Invoice`) produce the same hint without the prefix. `AddSource` throws on a duplicate hint name, and because the whole ecosystem is one `IIncrementalGenerator`, that exception aborts generation for **every** feature in the compilation. The visible symptom is a wall of CS0246 errors, not the duplicate-hint message.

The helper already handles the empty cases (a null, empty, or `"<global namespace>"` prefix is dropped), so there is no situation in which passing the model's namespace is wrong.

### Host Hints (Function-First)

In host projects, you search by purpose (entity config, DbContext, endpoints). The function comes first.

| Method | Pattern | Example |
|--------|---------|---------|
| `ForEntityConfig(entity)` | `EntityConfig.{Entity}.g.cs` | `EntityConfig.Invoice.g.cs` |
| `ForDbContext(boundary)` | `DbContext.{Boundary}.g.cs` | `DbContext.Billing.g.cs` |

### Sorting Convention

The underscore prefix (`_Boundary`, `_Infra`, `_Metadata`) sorts after letters in case-insensitive order, pushing infrastructure files to the bottom of the list:

```
Booking.Amenity.Create.g.cs
Booking.Amenity.Repository.g.cs
Sales.Invoice.Invoker.g.cs
_Boundary.Billing.Interface.g.cs
_Infra.Actions.Registration.g.cs
_Metadata.Persistence.g.cs
```

### Usage

```csharp
public override Artifact RenderOutput() => new(
    VirtualFolderHints.ForType(_model.TypeName, "Repository", _model.Namespace),
    ToSourceText());
// Produces: Sales.Invoice.Repository.g.cs
```

Never construct hint names manually. Always use `VirtualFolderHints` to ensure consistency across the entire generator.

## 12. EquatableArray and EquatableDictionary

These two live in `shared/SourceGen/` and exist for exactly one reason: **a model field must compare by value, or the incremental pipeline stops caching.**

### When you need them

Any time a model record that flows through the pipeline holds a collection. That is the whole rule.

### The problem they solve

`ImmutableArray<T>` looks like the right type and is not. It is a readonly struct wrapping a `T[]`, and its `Equals` compares the **array reference**, not the elements. A transform allocates a fresh array on every run, so a record holding one never equals its predecessor. The compiler-generated `Equals` returns `false`, the stage re-runs, the template re-renders, on every keystroke, forever. Nothing fails; the IDE just gets slower.

`ImmutableDictionary<TKey, TValue>` has the same defect.

### What you write

```csharp
using Pragmatic.SourceGen;

internal sealed record ValueObjectModel
{
    public required string TypeName { get; init; }

    public EquatableArray<ValueObjectParameter> ValidateParameters { get; init; }
        = EquatableArray<ValueObjectParameter>.Empty;
}
```

`EquatableArray<T>.Equals` walks the elements with `EqualityComparer<T>.Default`; `EquatableDictionary<TKey, TValue>` compares order-insensitively, matching dictionary semantics. A default-constructed `EquatableArray<T>` behaves as empty (`Count` is 0, enumeration yields nothing), so an unset field is safe, but assigning `.Empty` explicitly documents the intent.

### What you get

The conversion costs nothing at the call sites:

| Situation | What to do |
|-----------|------------|
| Transform ends in `.ToImmutableArray()` | Nothing. Implicit conversion wraps it on assignment. |
| Transform has an `IEnumerable<T>` | `.ToEquatableArray()` |
| You want a collection expression | `Imports = ["System", "System.Linq"]` works, via `[CollectionBuilder]` |
| Template needs an `ImmutableArray`-specific API | `.AsImmutableArray()` (returns empty for a default struct) |
| You have an `ImmutableArray<T>` in hand | `.AsEquatableArray()` |
| You need to read it | It is an `IReadOnlyList<T>`: indexer, `Count`, `Length`, `IsDefaultOrEmpty`, `foreach` |

### The one legitimate exception

`IncrementalValueProvider<ImmutableArray<T>>` (the type Roslyn's `.Collect()` hands you) stays as it is. That is pipeline plumbing, not a cached model field; Roslyn compares those elementwise itself. Wrap the fields *inside* the elements, not the provider.

```csharp
// Correct: provider stays ImmutableArray, the model inside uses EquatableArray.
var allActions = validActions.Collect();   // IncrementalValueProvider<ImmutableArray<ActionModel>>
```

The same applies to a template constructor parameter: `TemporalBehaviorsTemplate` takes an `ImmutableArray<TemporalBehaviorPropertyModel>` because it receives the collected array directly and is never itself cached.
